# 구현 지식

실제 코드와 실행 결과에서 확인했고 다음 작업에서도 사용할 사실을 기록합니다. 설계상의 의도는 [설계](../DESIGN.md)에, 작업의 결정과 진행은 [WORK](../work/index.md)에 남깁니다.

현재 기록된 구현 지식은 없습니다.

## 기록 원칙

먼저 기존 문서를 검색하고, 같은 주제의 지식이 있으면 갱신을 우선합니다. 대화 전체, 임시 디버깅 로그, 탐색 도구의 원본 출력은 보관하지 않습니다.

각 문서에는 다음 항목을 남깁니다.

- 문서 유형과 짧은 설명, 상태: 현재 확인한 사실인지, 재확인이 필요한지, 폐기된 내용인지 표시합니다.
- 출처: 저장소·파일 경로·조사 기준 커밋·확인 날짜. 실행 근거는 재현 방법과 확인 환경을 기록합니다.
- 확인한 사실과 한계: 소스 확인, 정적 검사, 브라우저·기기·운영 환경 확인을 구분합니다.
- 생성 주체(`generated`)와 사람의 검토(`verified`): AI 작성 여부와 사람의 검토 여부를 별개로 기록합니다. 자동 검사 통과를 사람의 검토로 표시하지 않습니다.
- 관련 설계·WORK·지식 링크와 변경 기록.

새 문서는 이 색인에 연결합니다. 근거 코드가 바뀌면 내용을 재확인하고 상태·출처·변경 기록을 갱신합니다. 설계와 다른 사실을 발견하면 관련 WORK에 차이를 남깁니다.

현재는 Markdown 기록 규칙만 정의되어 있습니다. OKF 스키마와 검증 도구는 연결하지 않았습니다. Graft 등 탐색 도구를 도입하더라도 결과는 재생성 가능한 캐시로 취급하고, 실제 소스를 확인한 내용만 지식으로 남깁니다.
