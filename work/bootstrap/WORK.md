# 기본 구조와 부트스트랩 문서 작성

## 목적과 범위

설계·작업 기록·구현 지식을 분리하는 운영 방식을 이 저장소의 초기 문서로 정리합니다. 기본 문서, 작업 양식, 다른 프로젝트에 적용할 수동 절차까지 포함합니다.

자동 설치 프로그램, 검사 스크립트, Git 훅 연결, OKF·Graft 설치, 다른 프로젝트 수정은 이번 범위에서 제외합니다.

## 완료 기준

- [x] 설계·작업 기록·구현 지식의 역할과 상호 참조 원칙을 기록한다.
- [x] 작업 상태와 설계 승인 상태를 분리해 정의한다.
- [x] 단일·다중 저장소의 관리 루트와 worktree 원칙을 기록한다.
- [x] 기존 파일을 보존하는 수동 부트스트랩 절차를 제공한다.
- [x] 문서 링크와 메타데이터의 일관성을 확인한다.
- [ ] 원격 `main` 이력을 이어 로컬 문서 전체를 커밋하고 push한 뒤 일치 여부를 확인한다.

## 설계 영향과 승인

- 관련 설계: [전체 설계](../../DESIGN.md).
- 2026-09-22 사용자 요청에 따라 기본 구조와 부트스트랩 문서를 작성한다.
- 문서 작성은 요청된 범위이며, 제안된 시스템 설계 전체에 대한 최종 승인은 아직 기록되지 않았다. 따라서 `approval: pending`으로 두고 구현을 진행하지 않는다.

## 작업 위치

- 관리 루트: 이 저장소의 루트.
- 원본 WORK: `work/bootstrap/WORK.md`.
- 저장소: `task-driven-dev`, 기준 브랜치 `main`.
- 기준 커밋: 작업 시작 시 커밋 없는 빈 저장소.
- worktree: 문서 작성만 하므로 생성하지 않음.

## 진행과 결정

- 2026-09-22: 기존 파일이 없음을 확인하고 기본 문서와 양식을 작성했다.
- 부트스트랩은 수동 적용 절차부터 정의한다. 자동화 도구가 연결되지 않은 상태를 문서에 명시한다.
- 제품별 내용이나 기존 Becon의 검사 결과를 이 저장소의 구현 사실로 복사하지 않는다.
- 2026-10-06: 사용자 요청 “원격이랑 맞춰서 로컬 작업 전부 원격으로 올려줘”에 따라 기존 문서 전체를 원격 `main`에 게시한다. 설계 승인 상태는 변경하지 않는다.
- 원격 `main`은 파일 없는 초기 커밋 `3da582a090a0dd14ac6fe3bad5c82a507e702245`이며, 로컬은 커밋 없이 문서 9개만 존재했다. 원격 이력을 이어서 커밋하며, 별도 `feat/*` 브랜치는 이번 동기화에 병합하지 않는다.
